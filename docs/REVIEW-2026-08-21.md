# Fresh-eyes review, 2026-08-21

An outside read of the whole repo against its own standard: everything transparent,
straightforward and reproducible. Nothing here was taken on trust — every finding below
carries the command that produced it, and the ones I could not verify say so.

Method: `kit next` / `kit audit` first, then `make check`, then the code, then the claims
in `TECH.md` re-derived from the rows in `data/`. No model was served; nothing needing a
live endpoint was checked.

## Verdict

The engineering is better than the evidence. The Go is disciplined, the comments explain
decisions rather than syntax, the gotchas list is the best artefact in the repo, and the
instruments distinguish "unmeasured" from "zero" almost everywhere — which is the hard
part. Where it breaks down is at the seam between the instruments and the documents:
**every conclusion is stated as measured, and about a third of them cannot be
regenerated from what is committed.** Two numbers in the most-cited table are simply
wrong. Half the rows predate the contamination instrument the vision requires, and
nothing says so.

None of the defects below reverses a decision. Several undermine the reason to believe
the decision.

## What earns its keep

- `docs/TECH.md#gotchas` — thirteen traps, each with the wrong number it cost. This is
  the thing most repos never write.
- The "unavailable is not zero" discipline: `ServerProps.Available`, `*_measured` flags,
  `Sampling` as pointers, `AcceptanceMeasured`. Consistently applied.
- `internal/eval/profile.go` and `config/machine.json` — the model's properties and the
  machine's limits are both data, and `grep -rn "57344\|65536\|49152\|32768" --include=*.go
  --include=*.sh .` returns nothing outside tests. That claim holds exactly.
- The decode-ratio table regenerates cell for cell (verified below).
- `runtimes/mlx/` and the losing harness configs — kept because a comparison nobody can
  re-run is not evidence. Correct, and cheap at ~160 lines.
- `config/agent.env` and `harness/claude-code/claude-code.env` — every variable carries
  why it is set and what was measured without it.

## Findings

Ordered by what they cost the reader's ability to trust the result.

### 1. Two numbers in the sampling table do not match the data they cite — HIGH

`TECH.md:418` claims 18.6 min and `TECH.md:421` claims 22.4 min. The file behind them
says 14.6 and 14.4.

```sh
go run ./cmd/report -results docs/data/2026-08-18-m2max-32gb-0005-toggle.jsonl
#   0005-off       wall 11.1 s mean × 27 =  5.0 min   TECH says  5.0  ✓
#   0005-on-low    wall 32.5 s mean × 27 = 14.6 min   TECH says 18.6  ✗
#   0005-on-medium wall 31.9 s mean × 27 = 14.4 min   TECH says 22.4  ✗
```

Seven of the nine cells in that table match their rows to the decimal, including every
`off` row and both other `on` rows. Only these two are wrong, and they are the two the
headline rests on: `TECH.md:434` concludes "**4× the wall clock** for 25/27 against
25/27", and `README.md:24` repeats it as the settled answer. The measured ratio is
**32.5 / 11.1 = 2.9×**.

The conclusion survives — 3× for no detectable gain still does not earn its cost — but
the number quoted in the two most-read documents is out by a third, and the claimed
ordering (medium slower than low) reverses in the data. Most likely a partial update when
the toggle file superseded the earlier figures; the other seven cells were refreshed and
these two were not.

**Fix:** correct three numbers, and add a `-summary` mode to `cmd/report` that prints the
suite total in minutes so the table has a generator.

### 2. Half the committed rows predate the contamination instrument — HIGH

The vision's rule: *"Runs record free memory and swap so contamination is detected rather
than assumed... a run that swapped is reported as void, not as a slow pass."*

```sh
python3 -c "
import json,glob
for p in sorted(glob.glob('docs/data/*.jsonl')):
    r=json.loads(open(p).readline())
    if not [k for k in r if 'swap' in k or 'mem_measured' in k]: print('no memory fields:', p)"
```

Six files, **399 of 834 rows (48%)**, carry no memory or swap field at all. They are the
evidence for four of TECH's conclusion sections: sampling and thinking, reasoning effort,
which tier-1 tasks carry signal, and tool-call adherence. `cmd/report` says so honestly —
"27 run(s) recorded no memory; cleanliness is unverified" on every config in the toggle
file — but neither `TECH.md` nor `data/README.md` mentions it, and the wall-clock column
of finding 1 is precisely the one paging corrupts.

This is not an argument to re-run them. It is an argument to label them, the way the page-size
erratum in `data/README.md` is labelled.

**Fix:** one line per affected file in `data/README.md`, and one sentence in each TECH
section that cites them.

### 3. `scripts/serve.sh` lets the ambient environment rewrite a committed config — HIGH

The config is *"the single source of truth for how a measurement was produced"* and the
script *"adds no flags of its own"*. It does when the shell that calls it has an opinion:

```sh
TEMP=0.5 SERVER_BIN=/bin/echo ./scripts/serve.sh config/tuned.env
# ... --parallel 1 --jinja --temp 0.5
```

`config/tuned.env` deliberately sets no sampling — TECH's serving section says a scorer
run *"must be served by a config that sets none of them, or the run measures something the
row does not say."* Any of `TEMP TOP_P TOP_K PRESENCE_PENALTY CHAT_TEMPLATE_KWARGS
CHAT_TEMPLATE_FILE SPEC_* JINJA METRICS HOST PORT CTX_SIZE PARALLEL` inherited from the
environment silently becomes a flag. The banner line prints only ctx, kv, host and port,
so the extra flag never appears in any log, and `Row` records `served_n_ctx` and
`served_model` but no sampling — so it never appears in the data either.

The repo already knows this hazard and has already solved it once, one directory over:
`internal/harness/claudecode.go`'s `EnvFromFile` strips every inherited `ANTHROPIC_*` and
`CLAUDE_*` for exactly this reason. The serving path never got the same treatment.

**Fix, cheapest first:** (a) have `Client.Props` also read `temperature`, `top_p`, `top_k`
and `presence_penalty` out of `default_generation_settings` — they are already in the JSON
`client.go:498` decodes, and four fields on `Row` make the leak visible in every results
file; (b) `unset` the optional names in `serve.sh` before sourcing; (c) echo the full
argument vector.

### 4. The documented exit-code contract is wrong in the case it names — HIGH

`cmd/eval/main.go:8-11` declares `2 = the run could not be carried out (bad flags,
unreadable fixture, **no server**)`. With no server:

```sh
go run ./cmd/eval -task tasks/patch-nil-check/task.json \
  -endpoint http://127.0.0.1:9 -results /tmp/r.jsonl -config probe; echo "exit=$?"
# eval: ... connection refused
# exit=1          <- contract says 2
# /tmp/r.jsonl was never created
```

`Props` failing only warns, and every per-task transport failure increments the same
`failures` counter as a wrong answer (`main.go:178` and `:192`), so exit 2 for "no server"
is unreachable. Worse: `internal/eval/task.go:258` carefully builds a
`FailServer` result *with the wall clock*, commented "recording zero would understate any
total this row is summed into" — and `cmd/eval` discards it and writes no row. `cmd/tier2`
records its `FailServer` rows. The two tiers disagree about whether a broken instrument is
part of the record.

The consequence is visible in the committed data: `data/README.md` explains one file with
*"The run did not finish, which is why there are 37 rows and not 42."* That gap is patched
by hand in prose because the tool dropped it.

Then both consumers of the contract throw it away — `Makefile:96` and `scripts/pair.sh:48`
both end in `|| true`, so a sweep against a dead server proceeds to `cmd/report`, which
summarises whatever the accumulating `results/tier1.jsonl` already held and exits 0. The
operator sees a normal-looking table.

**Fix:** write the `FailServer` row, return a distinct sentinel for transport failure, and
drop `|| true` from both call sites (branch on 1 vs 2 instead).

### 5. `TECH.md`'s flagship table cannot be regenerated by the tool that claims to — MEDIUM

`data/README.md:64`: *"Every table in ../TECH.md that one of these files backs can be
regenerated... reproduces the harness comparison and the decode ratios cell for cell. A
table that no longer regenerates is a defect in one of the two."*

The decode ratios do, exactly:

```sh
go run ./cmd/report -results docs/data/2026-08-20-m2max-32gb-0017-curve.jsonl
# depth-8000 1.40x · depth-16000 1.34x · depth-32000 1.26x — matches TECH cell for cell
```

The harness comparison does not. Two of its five columns are absent from the reporter:

| column | TECH | `cmd/report` |
|---|---|---|
| passed, turns, ingested/task | ✓ | ✓ |
| **context/turn** | 3,336 / 1,857 / 6,909 / 12,429 | not printed |
| **wall, clean rows** | 127.5 (5 of 15) | prints 98.4 — the all-rows mean |

The clean-row means are correct (I re-derived 127.5 / 63.6 / 96.8 / 299.4 under the
`>20 MB` rule), but they were computed somewhere that is not in the repo. By the file's own
sentence, that is a defect in one of the two.

**Fix:** add the two columns to `cmd/report`, or narrow the claim to the decode tables.

### 6. One void rule, two thresholds, one file — MEDIUM

`cmd/report/main.go:170` voids a run at `SwapDeltaMB > 20`, with a comment explaining the
slack: *"macOS moves swap around by a few MB without the run causing it, and flagging that
as contamination would cry wolf on every clean sweep."* 158 lines later, `main.go:328`
voids at `SwapDeltaMB > 0`, in the aggregator that produces the decode ratio — the number
the MTP adoption rests on. No reason is given for the difference, and the first comment
argues against the second rule.

It changes counts: under `>0` the Hermes cell is 9 clean rows and 307.1 s; under `>20` it
is 12 and 299.4 s, which is what TECH prints.

The same output also uses "unmeasured" for two different things — memory not measured
(`main.go:169`) and decode not measured (`main.go:322`) — and prints both, so the pair
report reads "1 run(s) recorded no memory" and "(13 unmeasured)" about the same 27 rows.

**Fix:** one named constant, one predicate, two distinct words.

### 7. Two memory probes, and the one that wrote the ladder uses the parse the other calls wrong — MEDIUM

`internal/eval/mem.go:60-72` keys every `vm_stat` counter off its label, with the reason:
*"vm_stat's field positions differ by macOS version, and a shifted parse records a
plausible number that is not the one the verdict rests on."* Same for `vm.swapusage`:
*"Keyed off the 'used' label rather than field position: three numbers of the same shape
sit on this line, and picking the wrong one records a plausible number."*

`scripts/memprobe.sh:34-40` parses both by field position — `{f=$3}`, `{w=$4}`, `{c=$5}`,
and `awk '{print $6}'` for swap. It is correct on this macOS today. It is also the
instrument that wrote `2026-08-17-m2max-32gb-ceiling-ladder.jsonl` and already produced one
erratum on the same counter.

**Fix:** port the label-keyed parse into the awk, or have the script call the Go probe.

### 8. The memory probe has no test that can fail — MEDIUM

`internal/eval/mem_test.go:28` calls the real `sampleMemory()` and `t.Skip`s when the
platform does not answer. CI is `ubuntu-latest`, so it always skips there; locally it
asserts only that three numbers are positive and that headroom is inside the machine. A
shifted field, a wrong label or a mis-scaled page — the two failures the gotchas record as
already having cost wrong numbers — all pass it.

The right shape is one file over: `thermal.go` splits `sampleThermal()` (exec) from
`parseThermal(string)` (pure), and `thermal_test.go` table-tests the parser. `mem.go` does
the parsing inline and cannot be tested that way.

**Fix:** extract `parseVMStat(out string, page float64) MemSample` and `parseSwapusage`,
and table-test them against captured `vm_stat` output. ~30 lines, and it runs in CI.

### 9. 0021 gated shell and markdown; Python is still ungated — MEDIUM

`make check` covers gofmt, vet, golangci-lint, shellcheck, shell options, doc links and
race tests. Nothing touches the 126 lines of Python. `scripts/deskverdict.py` holds the
desktop verdict *"in one place because two instruments now read it"* — a syntax error
there fails at run time, mid-sweep, in `ladder.sh` and `screen.sh` both. `scripts/doclinks.py`
is the gate itself and is executable without a shebang.

**Fix:** `python3 -m py_compile $(git ls-files '*.py')` in the `docs` target. One line.

### 10. The adopted decode speedup cannot be built from this repo — MEDIUM

`README.md`'s settled table says the answer is *"the model's own MTP head, at 32k only"*,
and `config/README.md` marks `mtp-32k.env` **Adopted for the grind profile**. That config
names `SERVER_BIN="$HOME/.local/src/llama.cpp-dflash2/build/bin/llama-server"`, a build of
an unmerged PR. The repo records the PR number and a fork commit SHA in a config comment
and gives no build recipe anywhere; `README.md`'s Getting Started tells a reader to install
Homebrew build 10450, which does not have it. `make serve` still serves `config/tuned.env`,
which does not speculate.

So the reproducible artefact for the adopted answer is a path in one person's home
directory. Against *"Reproducible over convenient. Every server invocation... lives in the
repo"*, this is the largest gap in the project.

**Fix:** commit the build recipe (four lines of `cmake`), or restate the verdict as
"measured, not adopted" until upstream merges. The second is honest and free.

### 11. Losslessness is greedy-only and is used to dismiss a sampled regression — MEDIUM

TECH's MTP verdict: *"Pass rate is 23/27 against 25/27... the identical greedy hash rules
that out as a distribution change."*

The fidelity probes run at `temperature 0, top_k 1` on three fixed short prompts
(`fidelity.go:44`). That establishes the decoder commits the same tokens *at greedy*, which
is exactly what licenses reading the speed number — the doc says so, correctly. It does not
establish that the sampled distribution at `temp 0.7` is unchanged, which is the claim the
sentence makes.

Where the two lost runs fall is worth knowing:

```sh
# both sides fail only on the two tasks TECH names as discriminating; the 12 flat ones are 3/3
patch-contradiction-rounding   mtp: over_budget, test_failed, pass   tuned: test_failed, pass, pass
toolcall-constraint-readonly   mtp: wrong_tool, wrong_tool, pass     tuned: wrong_tool, pass, pass
```

The suite behaved exactly as documented, and 2 runs on tasks known to sit at 1/3–2/3 is
noise either way. The defect is the word "rules out". By the vision's own standard — *"A
number that was derived rather than observed is a hypothesis, and it is labelled as one
until a run confirms it"* — this needs labelling.

**Fix:** either soften to "does not explain it as a distribution change", or add a seeded
sampled probe at the serving sampling, which llama.cpp supports per request.

### 12. A second copy of the context arithmetic, unchecked — LOW

`harness/claude-code/claude-code.env` sets `CLAUDE_CODE_MAX_CONTEXT_TOKENS="45056"`, which
is `config/agent.env`'s `CTX_SIZE` (49,152) minus `CLAUDE_CODE_MAX_OUTPUT_TOKENS` (4,096).
The comment states the derivation. Nothing computes it: change `agent.env` and the two
files disagree silently, and the symptom is the `exceed_context_size_error` the comment
exists to prevent.

**Fix:** one assertion in the Go test that already reads both files, or generate it in
`scripts/claude-code-settings.sh`.

### 13. The Go env parser and the documented shell reading disagree — LOW

`claude-code.env` is documented as shell-sourceable (`set -a; . file; set +a`) and is also
parsed by `internal/harness/claudecode.go:parseEnvFile`, whose comment says *"Strict on
purpose: a silently dropped variable serves a different configuration under the same
label."* It is not strict against the two things a shell handles:

```
ANTHROPIC_MODEL="qwen" # note   -> Go value: "qwen" # note      shell value: qwen
export FOO="bar"               -> Go name:  `export FOO`        shell: FOO=bar
```

Both are accepted without error; the second produces an environment entry the child
ignores. One format, two readers, different answers.

**Fix:** strip an unquoted trailing comment and reject a name that is not `[A-Za-z_][A-Za-z0-9_]*`.

### 14. `README.md:85` claims something one command does not do — LOW

*"Every command documents its exit codes at the top of `main.go`."* Five of six do;
`cmd/report` does not, and it exits 2. Small, but it is the kind of claim `make check`
cannot test and a reader will believe.

### 15. Smaller things

- **`internal/handoff/handoff.go:36`** matches `- [x] ` only. A box ticked `- [X]` — valid
  GFM — is not merely unticked, it vanishes from the list, so `Ticked()` returns false
  forever and the driver loops to its bound. This is the drift `BACKLOG.md` names as the
  promote trigger for reconciling the parser with `kit`; here is one instance of it.
- **`tasks/README.md`** says `depth/` is *"deliberately not picked up"* by `-tasks tasks`.
  It is not picked up because `DiscoverTasks` looks for `<dir>/*/task.json` and those
  fixtures are named otherwise. The exclusion is incidental, not declared: adding a
  `tasks/depth/task.json` breaks it silently. One sentence in the doc comment fixes it.
- **`scripts/doclinks.py:22`** strips `_` from anchors; GitHub keeps it. No heading uses
  one today, so the gate and GitHub agree by luck. It also cannot express the `-1` suffix
  GitHub appends to a duplicate heading.
- **`scripts/pair.sh:44`** writes server logs to `/tmp/pair-*.log`, outside the repo and
  outside `results/`. `pair.sh` is also the only server script that never calls
  `served_ctx`, which `lib.sh:55` describes as *"the guard against measuring one config
  under another's name, so a caller that skips it is claiming rather than checking."* The
  Go side records `served_n_ctx` per row, so the miss is covered — but it records rather
  than refuses.
- **`kit audit` reports MEDIUM `protocol-stale`** on `AGENTS.md`. The onboarding document
  every agent reads first is flagged superseded by the tool that wrote it, four commits
  after `04a240d Refresh the work protocol to the installed kit's`. Fix: `kit init .`

## What does not survive

- **`config/dflash2-32k.env` and `dflash2-49k.env`.** Kept as *"the record of a candidate
  that never generated a token here"*, but a config file is defined in this repo as the
  record of *how a measurement was produced* — and these cannot be run by anyone, on any
  machine, without a binary the repo does not describe how to build. The verdict is already
  in TECH's table and in `0017-screen.jsonl`, which is the durable record. Two files that
  are re-runnable only in principle.
- **`TECH.md`'s "one line each".** `AGENTS.md:24` says durable facts move to `TECH.md`,
  "one line each". It is 936 lines across 24 sections, several of them multi-paragraph
  arguments. The document is good and well-indexed — but either the rule is wrong or the
  document is, and right now the rule is not doing any work.
- **The thermal void rule.** `internal/eval/thermal.go` voids any run the machine capped —
  a durable property of how every number here is scored. It appears in `TECH.md` nowhere;
  its only prose home is the frozen `0017` doc. It has also never fired: `throttled`
  appears on 0 of 834 committed rows. That is fine (the budget guard is documented the same
  way — *"covered by a unit test, not by a live firing"*), but the rule belongs in TECH and
  the never-fired status belongs beside it.

## Suggested next step, in protocol shape

Findings 1, 2 and 3 are the ones that change what a reader may believe, and none is a
feature. Per `AGENTS.md`, they are a fix branch with no doc: correct the three numbers,
label the six uninstrumented files, and close the `serve.sh` env hole by recording the
served sampling on `Row`.

Findings 4–9 are one coherent feature — *the instruments record their own failures, and the
gate covers what they are made of* — and would be `kit new`'s next id. Findings 10 and 11
are questions for `docs/INBOX.md`, not decisions an agent should take: whether to commit a
build recipe for an unmerged PR, and whether to spend a run on a seeded sampled fidelity
probe.
